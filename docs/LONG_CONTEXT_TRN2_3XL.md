# Single-chip 12K context results

This note documents an experimental long-context configuration for Qwen3.8-27B on one Trainium2 chip. It contains no customer data; prompts used for the public smoke test are synthetic.

## Environment

- Instance envelope: trn2.3xlarge (1 Trainium2 chip, 96 GiB HBM, 12 vCPU, 128 GiB RAM)
- Precision: BF16 weights and KV cache
- Tensor parallelism: TP=4 (LNC2)
- Stack: public vLLM-Neuron 0.21 / Neuron SDK 2.31
- Model: text-only Qwen3.8-27B derivative generated by `make_local_model.py`

## Validated configuration

```bash
MODEL=/root/models/Qwen3.8-27B-text \
VLLM_CACHE_ROOT=/root/neff_cache/long_context_12k_mns4 \
VLLM_NEURON_DISABLE_PARALLEL_TRACE=1 \
MAX_LEN=12288 SEG=4096 BUCKETS=4096 KV_SEG=4096 \
MNS=4 GMU=0.90 KV_CAP=0.05 \
bash scripts/04_serve.sh
```

`KV_CAP` maps to `VLLM_NEURON_KV_GMU_BUDGET_CAP_FRACTION`. The plugin default of 0.30 reserved approximately 6.48 GiB per logical core for 419,744 KV tokens. This hybrid model has full KV on only 16 of 64 layers, so that allocation was far beyond this serving envelope and reduced memory available to DeltaNet state and runtime scratch.

With `KV_CAP=0.05`, the runtime allocated approximately 1.08 GiB per core for 69,952 tokens: 5.69 times the 12,288-token request length and above the 49,152-token worst case for four full-length requests.

## Smoke results

| Test | Result |
|---|---:|
| One synthetic long request | 9,062 input tokens, HTTP 200, 54 output tokens, 27.81 s |
| Four concurrent long requests | 4/4 HTTP 200; server remained ready |
| C4 wall time | 104.83 s |
| Peak HBM at C4 | 68.887 GiB/chip; 17.222 GiB/core |
| Functional endpoint suite | 5/5 |

The C4 wall time is approximately four times C1. This establishes capacity and stability, not four-way throughput scaling: segmented prefills are serialized by the current scheduler.

Sanitized raw artifacts are included in [`results/long_context_runtime.json`](../results/long_context_runtime.json), [`long_context_c1.json`](../results/long_context_c1.json), [`long_context_c4.json`](../results/long_context_c4.json), [`long_context_c4_memory.json`](../results/long_context_c4_memory.json) and [`endpoint_suite.json`](../results/endpoint_suite.json).

## Compilation caveat

Parallel graph trace produced `NCC_EVRF059` because generated HLO referenced NKI intermediate files removed before `neuronx-cc` consumed them. An isolated compile cache plus `VLLM_NEURON_DISABLE_PARALLEL_TRACE=1` produced a valid artifact in 1,912 seconds. Keep validated artifacts; compiler reproducibility is part of the deployment contract.

## Position relative to H100

These results demonstrate that single-chip Trainium2 can host the model in BF16 with >9K real input and four admitted requests. They do **not** establish performance parity with H100. A defensible comparison requires the same model revision, prompt/output token distributions, precision, schema constraints, warm-up policy and load generator on both platforms, followed by cost per successful request.

Current optimization priorities are paged decode for head dimension 256, an NKI segmented-attention path for head dimension 256, and reusable DeltaNet recurrent state for shared prefixes.
